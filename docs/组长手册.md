# 组长手册（李鹏飞专用）

> 组长的工作不是"多写一份报告"，而是**保证全组在截止时间前交得出能得分的作业**。
> 本文三部分：① 先把流程完整走一遍 ② 兜底清单 ③ 每周节奏与评审方法。

---

## 第一部分：先自己走一遍全流程

**目的**：把流程里所有的坑先踩一遍。你踩过的坑，组员就不会再踩；你跑通的路径，
直接变成给组员的范例（**你那个 PR 就是模板**）。

组员开工之前，你必须完成下面这条链路，并把结果留成"可被复制的范例"。

### 步骤 0：仓库准备（已完成 ✅）

- [x] 建立 `volcano-analysis` 仓库骨架
- [x] 5 位组员的报告目录与 `meta.yml`
- [ ] **在 GitHub 建 private 仓库并把组员加成 Collaborator**
- [ ] **给 `main` 加分支保护规则**：禁止直推、要求 1 个 approve、要求 `build_index.py --check` 通过
- [ ] 把 `.github/CODEOWNERS` 里的占位符换成真实 GitHub 用户名

### 步骤 1：向老师确认分析对象（★最高优先级，其他一切之前）

拿 [ADR-0002](adr/0002-adopt-volcano-as-subject.md) 的内容去问，
**把老师的原话记进 ADR 的「确认记录」表**。

要问清楚的三件事：

1. 教材要求"Spring PetClinic 或**教师指定的同规模**开源项目"，
   我们选 **Volcano（Go / K8s 批调度系统，体量更大）**，是否可以？
2. Go **没有继承**，而评分项要求"领域类图区分继承与关联"——
   我们用"接口实现 / 组合嵌入 / 关联 / 依赖"来替代，是否可以？
3. 报告是否**每人一份**？（教材口语上像是一份，但我们按每人一份准备）

> 这三个问题没确认之前，**不要让大家大规模开工**。
> 万一老师要求必须用 PetClinic，返工成本是 1 天；但如果写了三周才发现，就是三周。

### 步骤 2：自己完整跑一遍技术链路

```bash
bash scripts/fetch-baseline.sh        # 拉取 v1.15.3
bash scripts/setup-kind.sh            # 建集群 + 部署 Volcano
bash scripts/setup-kind.sh smoke      # 冒烟测试
```

- [ ] 把实际 K8s 版本填进 [baseline.md](../baseline.md) §3.1
- [ ] 写一份 ADR 记录 K8s 版本选择（模板：`docs/adr/0000-template.md`）
- [ ] 如果 arm64 上镜像有问题，把结论写进 ADR
- [ ] 把跑通过程中遇到的坑补成 `setup-kind.sh` 的注释

**这一步不做完，全组 5 个人都会卡在环境上，而且卡法各不相同。**

### 步骤 3：自己完整走一遍协作链路

- [ ] 认领一个模块（填进 [01-architecture.md](01-architecture.md) 的认领表）
- [ ] 开分支：`report/lipengfei/init`
- [ ] 填 `reports/lipengfei/meta.yml`
- [ ] 填 `templates/workbook.md` 的 B.1（仓库观察表）
- [ ] 跑一次真实调用链，留下 A 级证据记录
- [ ] 按 `templates/report.md` 写出 §1–§8
- [ ] 跑 `python3 scripts/build_index.py`
- [ ] 提 PR，用自己的 PR 模板自查一遍
- [ ] 合并

**完成后的产物**：一个填好的 `reports/lipengfei/` + 一个真实的 PR。
把这个 PR 链接发到群里，说一句："照我这个抄结构，不要抄内容。"

### 步骤 4：组织认领

- [ ] 开一次 30 分钟组会，过一遍 [教师要求解读](00-教师要求解读.md)
- [ ] 让大家在 [01-architecture.md](01-architecture.md) 的认领表上填名字（**可重复**）
- [ ] 确保**每个人都有一个明确的第一模块**（重复也没关系，重复的人自己再分工）
- [ ] 把 §7「维护观察」需要的 Issue 分配掉（见兜底清单）

## 第二部分：兜底清单

**兜底原则**：任何一个必交成果，如果没人认领或有人掉队，**你补**。
下面按"触发条件 → 你要做什么"列出。

### A. 老师确认（阻塞级）

| 触发条件 | 兜底动作 |
| --- | --- |
| 任何时候 | 立刻去问。得到答复后更新 ADR-0002 状态 |
| 老师否定 Volcano | 立即启动方案 B（Spring PetClinic），新建 ADR-0003，重排时间表。**方法可复用，不是从零开始** |

### B. 环境（阻塞级）

| 触发条件 | 兜底动作 |
| --- | --- |
| 有人卡在搭环境超过 2 小时 | 你把 `setup-kind.sh` 调通，写一份《环境排错》放 `docs/` |
| arm64 镜像有问题 | 写 ADR；必要时改用 x86 云主机，并把版本差异写进报告局限 |

### C. 五件必交成果

| 交付物 | 触发条件 | 兜底动作 |
| --- | --- | --- |
| ① 项目地图 | M2 时有人画不出来 | 你先出一版**底稿**放 `docs/01-architecture.md`（**但各人仍要自己画一遍**，必须能回答答辩第 5 问） |
| ② 领域对象图 | 有人类图关系标错 | 用 [教师要求解读 §8](00-教师要求解读.md) 的映射表逐个纠，重点是"嵌入 ≠ 继承" |
| ③ 调用链 | 有人只有成功路径 | 你补一条完整的**失败路径**范例（`minAvailable` 不满足），放进 `docs/02-scheduling-flow.md` |
| ④ 证据矩阵 | 有人 8 条全填"确认" | 直接打回：**全确认等于没核验**。要求至少 2 条"修正" |
| ⑤ AI 反思 | 有人写不出"被纠正"的案例 | 你分享自己的案例，但**不许他照抄** —— 答辩第 4 问会当场露馅 |

### D. §7 维护观察（最容易集体卡住的一项）

上游有 830+ 个 open issue，但"能拿来分析的"需要筛选。**这是你的活**：

- [ ] 从 https://github.com/volcano-sh/volcano/issues 挑 3–5 个成色好的
      （判断标准：现象清楚、能复现、涉及公共抽象、有讨论记录）
- [ ] 每个写两句话说明"为什么适合分析"，分给还没找到 Issue 的组员
- [ ] 如果实在挑不出来，退而用**选项 B：读一次代码历史**（挑一次有意义的提交）

### E. 模块覆盖

| 触发条件 | 兜底动作 |
| --- | --- |
| M1 结束时认领表有大片空白 | 你认领剩下的。**优先认领调度主流程**（`pkg/scheduler`），因为它被最多人依赖 |
| 有人中途退出 | 你接管他的模块；他的实验记录保留，报告由你补完并注明分工 |

### F. 收尾

| 触发条件 | 兜底动作 |
| --- | --- |
| M4 定稿 | 跑 `build_index.py --check`，确保索引与 `meta.yml` 一致 |
| 交作业前 | 逐份对照评分表复核；检查五件交付物是否齐全 |
| 交作业后 | 写 `reports/00-汇总.md`，做横向对比与组级结论 |

## 第三部分：每周节奏与评审方法

### 每周节奏

| 时间 | 你做什么 |
| --- | --- |
| 组会前 1 天 | 跑 `python3 scripts/build_index.py`，看谁没更新；逐个私聊催 |
| 组会前 | 合并积压的 PR（每条都要用评分表过一遍，不能只看格式） |
| 组会上（30 min） | ① 进度对齐 ② 挑 1 份报告当场用评分表打分并讲评 ③ 有新分歧就当场决定写不写 ADR |
| 组会后 | 更新 `reports/00-汇总.md` 的进度表；把新的风险加进本文件的兜底清单 |

### 评审 SOP（每条 PR 都照这个走）

1. **先看归属**：是不是只动了他自己的目录？
2. **按评分表找最弱项**：不要通读全文，直接去最低分的那个维度找证据
3. **抽查证据**：从证据矩阵里随机挑 2 条，自己动手核一遍（搜文件、看行号）
   —— 这是防止"证据是编的"的唯一办法
4. **检查五件交付物**：缺哪件直接打回
5. **检查 A 级证据**：少于 2 条的打回

### 组会可以固定问的三个问题

- "你从哪里知道？"（对应的文件/命令是什么）
- "如果我说相反，哪一段代码能证明你？"
- "这个箭头是静态关系还是运行时调用？"

（这三个问题是教材建议教师用的追问方式，你用来做组内互评同样有效。）

### 你需要最先建立的三个习惯

1. **不要替组员写报告。** 你替他写完，答辩时他答不上第 2、3 问，两个人都完蛋。
   兜底是"补空缺的模块"，不是"替他完成作业"。
2. **所有口径都落到文件里。** 群里说过的结论，24 小时内写进 ADR 或 `docs/`，
   否则三天后一定失忆。
3. **每周至少合并一次 PR。** PR 积压一周以上，作者就会失去动力，最后变成截止日前一天的灾难。
