# 组长手册（李鹏飞专用）

> 组长的工作不是"多写一份报告"，而是**保证全组在截止时间前交得出能得分的作业**。
> 本文三部分：① 先把流程完整走一遍 ② 兜底清单 ③ 每周节奏与评审方法。

## 第三部分：每周节奏与评审方法

### 每周节奏

| 时间 | 你做什么 |
| --- | --- |
| 组会前 1 天 | 跑 `python3 scripts/build_index.py`，看谁没更新；逐个私聊催 |
| 组会前 | 合并积压的 PR（每条都要用评分表过一遍，不能只看格式） |
| 组会上（30 min） | ① 进度对齐 ② 挑 1 份报告当场用评分表打分并讲评 ③ 有新分歧就当场决定写不写 ADR |
| 组会后 | 更新 `reports/00-汇总.md` 的进度表；把新的风险加进本文件的兜底清单 |

### 评审 SOP（每条 PR 都照这个走）

1. **先看归属**：是不是只动了他自己的目录？
2. **按评分表找最弱项**：不要通读全文，直接去最低分的那个维度找证据
3. **抽查证据**：从证据矩阵里随机挑 2 条，自己动手核一遍（搜文件、看行号）
   —— 这是防止"证据是编的"的唯一办法
4. **检查五件交付物**：缺哪件直接打回
5. **检查 A 级证据**：少于 2 条的打回

### 组会可以固定问的三个问题

- "你从哪里知道？"（对应的文件/命令是什么）
- "如果我说相反，哪一段代码能证明你？"
- "这个箭头是静态关系还是运行时调用？"

（这三个问题是教材建议教师用的追问方式，你用来做组内互评同样有效。）

### 你需要最先建立的三个习惯

1. **不要替组员写报告。** 你替他写完，答辩时他答不上第 2、3 问，两个人都完蛋。
   兜底是"补空缺的模块"，不是"替他完成作业"。
2. **所有口径都落到文件里。** 群里说过的结论，24 小时内写进 ADR 或 `docs/`，
   否则三天后一定失忆。
3. **每周至少合并一次 PR。** PR 积压一周以上，作者就会失去动力，最后变成截止日前一天的灾难。
