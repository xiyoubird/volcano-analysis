## 背景

课程材料 `docs/elearn/` 中的作业要求（教材 §8.1）原文为：

> 你将以 **Spring PetClinic** 或教师指定的**同规模**开源项目为对象，完成一份"项目理解报告"。

本组选择的分析对象是 **Volcano**（`volcano-sh/volcano`，Go，CNCF incubating，
Kubernetes 原生批调度系统，基线 `v1.15.3`）。选择原因：

- 组员对 Kubernetes / 云原生方向更感兴趣，与后续学习方向一致；
- Volcano 有完整的作业模型（Job / PodGroup / Queue）、清晰的分层与大量真实 Issue，
  能自然覆盖教材要求的全部实训单元；
- 上游处于活跃维护状态，Issue 与提交历史材料充足。

但与教材案例存在两处实质偏离，见下表。

## 决策

**采用 Volcano 作为分析对象**，前提是教师确认。同时用以下方式消除偏离带来的可评分性风险。

## 偏离与应对

| # | 偏离 | 为什么是风险 | 应对措施 |
| --- | --- | --- | --- |
| 1 | **语言不同**：教材全篇是 Java + 面向对象（继承、Service 层、Controller 构造器注入） | 评分项「核心类与关系 15 分」要求"区分**继承**与关联"，而 **Go 没有继承机制** | 使用 [教师要求解读 §8](../00-教师要求解读.md) 的映射表：接口实现 → 虚线空心三角；struct 嵌入 → 标为**组合**并显式说明"嵌入 ≠ is-a"；把"Go 无继承"本身写成 §3 的一个分析点，正好回答答辩第 2 问 |
| 2 | **规模不同**：Volcano 比 PetClinic 大两个数量级（`v1.15.3` 含 24 个调度插件、8 个 Action、7 类 admission webhook） | 教材要求"**同规模**"项目，字面上不满足 | **由组长向教师口头确认**。同时控制报告范围：每人只对**自己认领的模块**做深度分析，但项目地图/调用链覆盖全局，保证单份报告可读、可评 |

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 直接用 Volcano（选中） | 兴趣匹配；材料丰富；与组员方向一致 | 需教师确认；Go 无继承需额外说明 | 采纳，**但以教师确认为前提** |
| B. 改用 Spring PetClinic | 完全符合教材，零风险；有现成的教师参考答案 | 5 个人分析同一个小 demo，报告会同质化；组员兴趣低 | 备选。**若教师否定方案 A，立即切换**（工作量约 1 天） |
| C. 两套都做：PetClinic 交作业 + Volcano 作扩展 | 万无一失 | 工作量翻倍，且教材明确警告"不要贪多" | 不采纳，除非教师要求 |

## 理由

1. 教材反复强调"学习的不是 PetClinic，而是一套进入陌生项目的方法"（讲义第 60 页）。
   评分维度考察的是**方法**——结构侦察、对象关系、调用链追踪、证据判断——
   这些能力在 Go 项目上同样可被考察，且更接近真实工程。
2. Volcano 的领域对象（Job / PodGroup / Queue / Node / Resource）层次清晰，
   满足"至少 5 个核心类"的要求没有困难。
3. 风险是**可管理**的：主要风险是教师不认可对象选择，而这一点可以在开工前一小时问清楚。

## 后果

- **好的后果**：全组兴趣匹配；报告有真实的工程深度；能产出对上游有价值的 Issue 分析。
- **坏的后果 / 代价**：
  - 若教师否定，需要切换到方案 B，损失约 1 天（但项目地图/类图/调用链的**方法**可以复用，返工不是从零开始）。
  - Go 的类型关系需要在报告中额外解释，占用一定篇幅。
  - 教材附录 A 的提示词模板全是 Java 语境，需要改写成 Go/Volcano 语境（见 [教师要求解读 §8](../00-教师要求解读.md)）。
- **需要同步更新的文件**：`docs/00-教师要求解读.md`、`templates/*.md`（提示词示例）、`baseline.md`。

## 复审条件

1. 教师明确否定 Volcano → 立即转为方案 B，并新建 ADR-0003 记录切换；
2. 教师认可的但附加了条件（如"必须也覆盖教材里的 OOP 概念"）→ 更新本 ADR 的应对措施；
3. 项目进行到中期发现 Volcano 的某个必交成果（如调用链）无法完成 → 重新评估。
